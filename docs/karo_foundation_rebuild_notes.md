# Karo Foundation Rebuild Sprint — Notes

## Почему мы делаем этот спринт?
Текущая версия десктопного приложения Karo является практически полной симуляцией. Проект хранит задачи, прогоны агентов, артефакты и состояние конвейера исключительно в оперативной памяти WebView2. Физическое применение изменений к файлам на диске отсутствует либо реализовано в виде заглушек, а перезапуск приложения полностью стирает всю историю работы.

Чтобы превратить Karo из красивого макета в реальный инструмент локальной разработки, мы проводим **Foundation Rebuild Sprint**. Наша цель — построить надежный, безопасный и долговечный фундамент для выполнения файловых операций и сохранения состояния на физическом диске.

---

## Какие проблемы мы чиним?
1. **Отсутствие реальной записи (Apply Changes):** Изменения файлов, сгенерированные агентами (Coder/Fixer), теперь будут безопасно применяться к файлам внутри корня проекта.
2. **Уязвимость путей (Write Safety):** Реализация строгой валидации путей в Rust (защита от path traversal, запрет на выход за пределы проекта, блокировка перезаписи чувствительных файлов типа `.env`).
3. **Отсутствие Staging-окружения:** Перед записью в основную рабочую область изменения будут сохраняться в изолированной директории `.karo/staging/task_<id>`.
4. **Потеря истории после перезапуска:** Все задачи (`TaskRun`), отчеты, артефакты и прогоны теперь будут сохраняться на диске в формате JSON в директории AppData приложения, переживая перезапуски Karo.
5. **Неработающие Tauri-команды:** Заглушки настроек и ключей будут заменены на работоспособные локальные команды хранения.

---

## Какие проблемы мы пока НЕ чиним?
- **Полный редизайн интерфейса:** Дизайн-система остается прежней (стеклянный темный UI на VanillaJS).
- **Переход на другие фреймворки:** Весь код UI `workbench.ts` остается в текущей архитектурной схеме.
- **Облачная синхронизация / Marketplace:** Все агенты и прогоны остаются локальными.
- **Сложный AST Context Engine / Векторные БД:** Контекст считывается через оптимизированный `readProjectSummary`.
- **Автоматический запуск shell-команд:** Любые команды требуют согласия пользователя (Consent Gate) и в рамках этого спринта запускаются только по явному разрешению.

---

## Acceptance Criteria (Критерии приемки)
1. Пользователь создает задачу в UI.
2. Агент Coder генерирует артефакты, которые успешно записываются в реальную папку `.karo/staging/task_<id>`.
3. В интерфейсе (вкладка **Changes**) отображается разница (diff) или список измененных файлов.
4. При клике на **Apply Changes** Tauri-бэкенд на Rust производит резервную копию файлов и безопасно перезаписывает их в корневом каталоге проекта.
5. После перезапуска Karo история задачи, прогонов и примененных изменений остается доступной в панели **Runs**.
6. Любые попытки агента прочитать или записать файлы за пределами корневой папки проекта или изменить файл `.env` блокируются бэкендом с выдачей понятной ошибки безопасности.

## Reliability Sprint Verification

Для ручной и автоматической верификации работоспособности и надежности конвейера применения (Apply Pipeline) используйте следующие команды в PowerShell:

### PowerShell Verification Commands

```powershell
# 1. Проверить, что целевой файл успешно создан и содержит правильные данные
Get-Content "D:\проекты\karo-test\src\karo-test-output.txt" -Raw

# 2. Проверить структуру изолированного staging-окружения (.karo/staging) и бэкапов
Get-ChildItem "D:\проекты\karo-test\.karo" -Recurse -Force |
Select-Object FullName, Length, LastWriteTime

# 3. Проверить создание постоянного хранилища и истории в AppData
Get-ChildItem "$env:APPDATA\com.ai-agent-orchestrator.desktop" -Recurse -Force |
Select-Object FullName, Length, LastWriteTime
```

### Acceptance Criteria
- **file exists**: файл `src/karo-test-output.txt` реально создается по целевому пути.
- **content correct**: содержимое файла строго соответствует `"hello from real Karo apply pipeline"`.
- **staging exists**: папка staging `.karo/staging/task_<id>` успешно создается с копией измененных файлов перед накатом.
- **tasks.json exists**: файл `tasks.json` и `settings.json` успешно создаются в каталоге `%APPDATA%\com.ai-agent-orchestrator.desktop` для долговременного хранения истории.
- **backups created**: при перезаписи файла создается резервная копия рядом с файлом путем добавления суффикса `.bak` (например, `src/karo-test-output.txt.bak`), а путь выводится в `ApplyResult`.
- **blocked paths rejected**: любые попытки записи в `../outside.txt`, абсолютные пути вне проекта, `.env`, `.env.local`, `.git/config` и `.git/HEAD` строго блокируются на уровне бэкенда с понятной ошибкой `PermissionDenied`/`OutsideWorkspace`, а в UI выводится статус блокировки.
- **cargo check no warnings**: компиляция бэкенда проходит с результатом `0 warnings`.
- **cargo test no warnings**: юнит-тесты бэкенда на Rust (включая безопасность путей и обход папок) проходят успешно без предупреждений.
- **tsc passes**: сборка типов фронтенда компилируется без ошибок (`tsc --noEmit` успешно проходит).

## Execution Mode UX Decision

Karo is a desktop-first real workspace app.
Live backend pipeline is the default.
Simulation mode exists only for developer/testing/debug fallback.
Normal users should not choose between demo and real.
If backend is offline, Karo must show a clear warning/error and must not pretend changes were applied.
Simulation mode must not show real apply success.
