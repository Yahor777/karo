# Contributing to Karo

Karo is in an MVP checkpoint phase. Keep changes small, testable, and honest about what is working.

## Development Rules

- Do not commit generated artifacts:
  - `apps/desktop-windows/e2e-artifacts/`
  - `.karo/staging/`
  - `karo-before-*.patch`
  - screenshots/reports/logs
  - `.env*`
  - `.codex/` autogenerated local environment files unless intentionally reviewed
- Do not print or persist provider API keys.
- Do not add fake UI controls. If a control is visible, it must either work or clearly say why it is unavailable.
- Keep Chat / Plan / Agent / Auto behavior distinct.
- Keep Quick Edit for trivial file tasks and the full agent pipeline for larger coding tasks.

## Local Checks

Run before proposing a checkpoint:

```powershell
cargo check
cargo test
pnpm --filter @ai-agent-orchestrator/desktop-windows exec tsc --noEmit
pnpm test
pnpm --filter @ai-agent-orchestrator/desktop-windows gui:check
pnpm --filter @ai-agent-orchestrator/desktop-windows gui:check:tauri-runtime
git diff --check
```

## Product Bar

Karo should feel like an AI IDE, not a debug harness:

- the first screen explains what to do;
- the composer stays simple;
- advanced controls stay in Advanced/Settings;
- right inspector tabs are relevant to the current run;
- agent activity is readable and raw diagnostics are collapsed;
- Preview/Terminal behavior is real or clearly marked as limited.
